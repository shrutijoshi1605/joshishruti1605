LAYER 3 — AUTO-CLASSIFICATION ENGINE
How data is labelled automatically, without trusting users who may apply wrong tags
THE RISK
A user uploads a file and marks it Internal because it looks like routine data. But it contains NHI numbers and medical conditions they did not notice. Without automatic detection, that data is stored without clinical-role restrictions, without masking, and without the retention rules required by the NZ Privacy Act. The obligation is silently broken.
01
Column Header Matching
Column nhi_number flagged as HEALTH before any row is read
Column balance flagged as FINANCIAL from the header alone
Column medical_condition triggers HEALTH classification
Column ird_number flagged as FINANCIAL (NZ IRD identifier)
Fastest layer. Fires on file structure before content is read.
02
Regex Pattern Scanning
NHI format: /[A-Z]{3}\d{4}/ matched on every row
IRD format: /\d{3}-\d{3}-\d{3}/ across all columns
NZ phone: /(\+64|0)[2-9]\d{7,9}/
Account: /\d{4}-\d{4}-\d{4}-\d{4}/
Catches sensitive data even in misnamed columns.
03
NLP Keyword Detection
Medical condition dictionary: 3,200 clinical terms
Person name entity recognition in free-text fields
Location text geocoding for address fields
Compensation keyword match for salary-adjacent values
Catches sensitive data in unstructured text with no fixed format.
TIER ASSIGNMENT RULES — highest detected type always wins
PUBLIC
No sensitive pattern detected in any column
INTERNAL
Operational data only — no PII, financial, or health
CONFIDENTIAL
PII detected, or Financial detected (not combined)
RESTRICTED
Health data detected, or PII and Financial combined
User tag override: If a user labels data at a lower tier than what the engine detects, the system automatically upgrades the tier and logs the discrepancy to the immutable audit trail. Users cannot downgrade sensitive data accidentally or intentionally.
